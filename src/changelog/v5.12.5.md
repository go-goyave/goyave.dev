# v5.12.5 release notes

- lang: a quality value of 0 for a language listed in the `Accept-Language` header is now considered unacceptable in order to comply with (RFC 9110 section 12.4.2). The server won't use an unacceptable language anymore unless it's the default language and no other accepted language is available.
- compress: a quality value of 0 for an encoding listed in the `Accept-Encoding` header is now considered unacceptable in order to comply with (RFC 9110 section 12.4.2). The middleware won't use an unacceptable encoding anymore. Clients can disable compression entirely by specifying `Accept-Encoding: *;q=0`. See the `compress.Middleware` docs for more details.
